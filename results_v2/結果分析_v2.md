# AI 生成 SPICE 實驗 v2：自動除錯迴圈 + 重複實驗

## 實驗設定
- 模型：qwen2.5-coder 7B、qwen3.5 9B（本機 Ollama，Colab L4）、Gemini 3.5 Flash（雲端 API）
- 題目：RC 低通（fc=1kHz）、共源極放大器（20dB）、兩級 CMOS OPA（≥60dB）
- Prompt：simple / detailed；每組重複 3 次 → 3 × 3 × 2 × 3 = **54 組**
- 除錯迴圈：失敗時把 ngspice 錯誤訊息或「量測值 vs 規格」回傳給 AI，最多修正 3 輪
- 驗證：ngspice AC 分析，程式自動量測、判定

## 一、總結果（54 組）
| 模型 | 第一次通過 | 修正 ≤3 輪後 | 提升 |
|---|---|---|---|
| qwen2.5-coder 7B | 0/18（0%） | 1/18（6%） | +1 |
| qwen3.5 9B | 4/18（22%） | 8/18（44%） | **翻倍** |
| Gemini 3.5 Flash | 17/18（94%） | 18/18（100%） | +1 |

## 二、各輪累積通過率（%）
| 模型 / Prompt | 第 0 輪 | 第 1 輪 | 第 2 輪 | 第 3 輪 |
|---|---|---|---|---|
| Gemini / simple | 100 | 100 | 100 | 100 |
| Gemini / detailed | 89 | 100 | 100 | 100 |
| qwen3.5 9B / detailed | 33 | 44 | 56 | **67** |
| qwen3.5 9B / simple | 11 | 22 | 22 | 22 |
| qwen2.5 7B / simple | 0 | 11 | 11 | 11 |
| qwen2.5 7B / detailed | 0 | 0 | 0 | 0 |

→ qwen3.5 + detailed Prompt 每多修一輪就再進步，3 輪還沒飽和；simple Prompt 修 1 輪後就卡住。

## 三、各題通過數（第一次 → 修正後，每格滿分 6）
| 題目 | qwen2.5 7B | qwen3.5 9B | Gemini |
|---|---|---|---|
| RC 低通 | 0 → 1 | 4 → 5 | 6 → 6 |
| CS 放大器 | 0 → 0 | **0 → 3** | 6 → 6 |
| 兩級 OPA | 0 → 0 | 0 → 0 | 5 → 6 |

## 四、除錯迴圈修好了什麼、修不好什麼
### 修得好（qwen3.5、Gemini）
- **輸出節點沒命名成 `out`**（`no such vector out`）：qwen3.5 CS detailed 3 次全部在 1–3 輪內修好 → 通過
- **缺 `.model` 定義**（`could not find a valid modelname`）：qwen3.5 CS simple 修好語法
- **回授極性接反**：Gemini OPA detailed r3 第一次 spec_fail（同第一版的錯誤），收到「增益未達 60 dB」回饋後 1 輪就修正差動對正負端 → 86 dB 通過

### 修不好
- **qwen2.5 7B 看不懂錯誤訊息**：17 組用完 3 輪修正，其中 **10 組連續 3 輪犯完全相同的錯**（例如 `vss 2 0 device already exists` ×4、`w1=10u l1=1u` ×4）
- **qwen2.5 把說明文字寫進 netlist**：11/18 組在修正時把英文解釋（"In this corrected netlist, I have ensured…"）直接寫進電路檔 → 製造新的語法錯誤，越修越糟
- **qwen3.5 CS simple**：語法修好了，但電路拓樸錯，增益 -134 dB，3 輪都沒找到原因 → 能修「語法」，不能修「設計觀念」
- **兩級 OPA**：qwen3.5 6 組全失敗，反覆出現短路電壓源（`vgnd is a shorted VSRC`）、節點數錯誤

## 五、重要觀察
1. **錯誤回饋讓中型模型（9B）通過率翻倍**，但對 7B 幾乎無效 → 回饋迴圈有用的前提是模型「看得懂」錯誤訊息。
2. **Prompt 和回饋會疊加**：qwen3.5 detailed 從 33% 升到 67%，simple 只從 11% 升到 22%。
3. **小模型修得好語法，修不好設計**；大模型第一次就幾乎全對，唯一的設計錯誤（回授極性）也能靠「規格未達」的回饋修好。
4. **單次實驗不可靠**：第一版（每組 1 次）Gemini 的 OPA 0/2 失敗；v2 重複 3 次後第一次通過率 5/6。只跑一次會嚴重低估或高估，所以重複實驗是必要的。
5. **Gemini 的 OPA 設計品質**：開迴路增益 86–107 dB；simple 版本自動把第二級尺寸設計成「零系統性偏移」條件 (W/L)₆/(W/L)₄ = 2·(W/L)₇/(W/L)₅，例如 200/20 = 2·(100/20)，所以沒有 DC 回授也能偏壓在高增益區。

## 六、限制
- Level-1 MOS 模型、無寄生電容：頻寬與高頻行為不代表真實電路
- simple Prompt 的 OPA 測試電路沒有 DC 回授，靠模擬中元件完全匹配才能偏壓；實際電路會因偏移而飽和
- 每組 3 次，樣本仍小；Gemini 免費額度有每日上限，曾因額度用完中斷後續跑
- 生成時間包含 API 等待重試，不代表模型本身速度
